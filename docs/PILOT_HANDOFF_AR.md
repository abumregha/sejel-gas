# سجل — رسالة التسليم الحالية

**التاريخ:** 3 أكتوبر 2026 · **الدورة:** 11:00 ← 11:00 · **المحطة التجريبية:** `محطة تجريبية — سجل`

هذه الوثيقة الوحيدة الحالية. التقارير التاريخية (جولات 1–3) باقية في تاريخ git.

---

## 1. ما هو سجل

نظام إدارة محطات وقود: قراءات عدادات المضخات، تحصيل نقدي وقسائم، مخزون
(شحنات، قراءات خزانات، تحويل بين خزانات، نقص)، تقارير مالية يومية وشهرية،
وتقرير Excel قابل للتصدير. الواجهة عربية بالكامل وتعمل على الهاتف.

## 2. دورة العمل اليومية (11:00 ← 11:00)

1. **تعريف المناوبة** — لكل جزيرة مضخة ووقت بداية/نهاية (الافتراضي 11:00).
2. **بدء المناوبة** — من صفحة التفاصيل («▶ بدء المناومة») → تصبح `open`.
3. **قراءات المضخات** — كل مسدس قراءة بداية ونهاية؛ نهاية اليوم = بداية الغد.
4. **الإيراد** — تحصيل نقدي، قسائم، نقاط بيع، مصروفات.
5. **إقفال المناوبة** ثم **إقفال اليوم** — يولّد التسوية المالية.
6. **التقارير** — يومي/شهري/Excel، محطة واحدة أو كل المحطات.

## 3. قراءات المضخات

- **القراءة الافتتاحية:** أول قراءة لعداد لم يُقرأ من قبل تُعلَّم `is_opening`
  وتسجّل **0 لتر** (ليست بيعًا). القراءة التالية تحسب بشكل طبيعي ضدها.
- **الاستمرارية:** قراءة البداية يجب أن تساوي آخر قراءة نهاية. أي فجوة أو
  عدّاد أقل من السابق **مرفوض** إلا مع **نوع الاستثناء + سبب مكتوب**:
  - `تصفير` / `استبدال` → اللترات المباعة = قيمة العدّاد الحالية.
  - غير ذلك → 0 لتر، والسبب يبقى في السجل للمراجعة.
- القيم العشرية مقبولة، والقيم الضخمة (20 رقمًا) تُرفض برسالة عربية.

## 4. إقفال اليوم

زر «إقفال اليوم» في صفحة القراءات (يظهر لمن يملك الصلاحية). اليوم المُقفل
للقراءة فقط؛ إعادة الفتح إجراء إداري. كل إقفال يوم يولّد `Shift` خاصًا
يحمل القراءات والإيراد والتسوية.

## 5. القواعد المالية

```
المحسوب  = Σ liters_sold
المتوقع  = Σ liters_sold × سعر البيع   (لكل نوع وقود)
المحصّل  = نقدي + قسائم + نقاط بيع
الفرق    = المحصّل − المتوقع          (سالب = عجز)
الصافي   = المحصّل − المصروفات
```

- التحويل بين خزانين: نفس المحطة، نفس نوع الوقود، الكمية > 0، **المصدر لا ينزل
  تحت الصفر**، والوجهة **لا تتجاوز سعتها**، ويُطبَّق **مرة واحدة فقط**.
- حذف سجل مرتبط بسجلات مالية **محظور عمدًا** — الواجهة تشرح بالعربية أي
  السجلات المرتبطة يجب حذفها أولًا.

## 6. الأدوار وحسابات الدخول

### 6.1 حسابات الدخول الفعلية — ثلاثة فقط

| البريد (أو المختصر) | الدور | الصلاحية |
|---|---|---|
| `admin@sejel.ly` / `admin` | System Manager | كل شيء، كل المحطات |
| `owner@sejel.ly` / `owner` | Sejel Manager | كل المحطات، الإدارة |
| `emp@sejel.ly` | Sejel User | موظف محطة، مقيّد بمحطته فقط |

- كلمات المرور **تُسلَّم منفصلًا** ولا تُكتب في هذا الملف (المستودع عام).
- شاشة الدخول: الحقل الأول **اسم المستخدم** (البريد) والثاني **كلمة المرور**.
  إدخال كلمة المرور في الحقل الأول يرجع `401` مع الرسالة العامة
  «خطأ في بيانات الدخول» — وهذا ما حدث في محاولة الدخول الأولى للعميل
  (٦ محاولات، الحقل الأول كان يحمل `owner123`/`admin123`).
- أسماء مثل `manager` و`supervisor` و`finance` **أدوار صلاحيات في Frappe وليست
  حسابات دخول** — لا وجود لها في قاعدة البيانات، فلا تُكتب في خانة المستخدم.

### 6.2 الصلاحيات حسب الدور

| الدور (Frappe) | الصلاحية |
|---|---|
| System Manager | كل شيء، كل المحطات |
| Sejel Manager | كل المحطات، الإدارة |
| Sejel Supervisor | تشغيل المحطة (مناوات، قراءات، موظفون، تحويل خزانات) — مقيّد بمحطته إذا كان له `sejel_station` |
| Sejel Finance | مالي (تحصيل، قسائم، مصروفات، تسويات) — يُقيَّد بالطريقة نفسها |

- المستخدم المقيّد **لا يرى ولا يكتب** بيانات محطة غيره: القوائم مُرشّحة من
  الخادم، وقراءة/تعديل/إنشاء لسجل أجنبي يرجع `403`.
- كل نقاط الـ API تتطلب جلسة؛ لا يوجد أي مسار بيانات للزوار.

## 9. محدوديات معروفة

- **لا توجد اختبارات Python** في التطبيق (صفر ملفات `test_*.py`) — كل
  الضمانة من اختبارات المتصفح أعلاه.
- **Frappe يرفض حذف مستخدم له سجلات** (417 «You can disable this User…») —
  استخدم زر «تعطيل» في شاشة المستخدمين (يؤدي نفس الغرض ويزيل ربط المحطة).
- **حذف محطة لها سجلات مالية محظور** وتظهر رسالة عربية تسمّي السجلات المرتبطة.
- **العداد (Meter) غير قابل للحذف** عبر الـ API — تُعاد قيمته من القراءات المتبقية.
- السكربتات القديمة (`phase1-master-data.js` · `phase9-user-journey.js` ·
  `verify-fixes.js` · `qa-verify-qa32.js`) **خارج** المجموعة المعتمدة (205)
  ولا تدخل في الرقم النهائي. أُصلحت فيها الخطوات التي كانت لا يمكن أن تفشل
  (دعم `true` الثابت و`every()` على قائمة قد تكون فارغة) في commit `206cc75`.
  لم تُشغَّل بعد: تنشئ محطات وأيام تجريبية وتعتمد على معرّفات ثابتة، فلا
  تعتمد عليها لأرقام النتيجة.
